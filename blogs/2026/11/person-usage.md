## 适用范围

本文适用于以微信小程序为主要目标、同时预留 App 和 H5 发布能力的 uni-app 项目。业务代码、页面、组件和 AI 生成代码都必须遵守本规范。

规范优先级：平台限制 > 本文强约束 > 组件约定 > 页面局部样式。页面不得自行创建第二套颜色、字号、间距或层级体系。

## 技术栈规范

| 类别     | 技术选型                      | 说明                                            |
| -------- | ----------------------------- | ----------------------------------------------- |
| 应用框架 | uni-app + Vue 3               | 使用 Composition API，不混用 Vue 2 写法         |
| 开发语言 | JavaScript                    | 不使用 TypeScript；公共方法必须补充 JSDoc       |
| 构建工具 | Vite + pnpm                   | 统一使用 CLI 工程和 pnpm                        |
| 状态管理 | Pinia                         | 仅跨页面或跨组件共享状态进入 Store              |
| 样式语言 | SCSS                          | Token、函数、Mixin 和组件样式统一使用 SCSS      |
| 请求层   | `uni.request` 二次封装        | 业务页面禁止直接调用 `uni.request`              |
| 日期处理 | dayjs                         | 禁止业务代码手写日期解析和格式化                |
| 工具库   | xe-utils                      | 通用对象、数组、字符串和数据处理优先复用        |
| 图标     | 项目统一图标集                | 禁止 Emoji 充当业务图标，禁止页面各自引入图标库 |
| 代码规范 | eslint + @antfu/eslint-config | 提交前统一检查，禁止页面局部关闭规则            |
| 测试     | Vitest                        | 重点覆盖 utils、请求层、Store 和业务状态转换    |
| UI 组件  | 项目自有基础组件              | 禁止同时引入多个第三方 UI 库形成多套视觉语言    |

## 目录结构规范

| 目录                      | 职责         | 约束                                          |
| ------------------------- | ------------ | --------------------------------------------- |
| `src/pages`               | 主包页面     | 只保留页面入口和页面编排                      |
| `src/pages-sub`           | 分包页面     | 按业务域拆分，不跨分包反向引用页面代码        |
| `src/components/base`     | 基础 UI 组件 | Button、Popup、Empty、Image 等无业务组件      |
| `src/components/business` | 通用业务组件 | 具有明确业务语义，可被多个页面复用            |
| `src/api/modules`         | API 模块     | 一个业务域一个 API 文件                       |
| `src/core`                | 项目级能力   | request、auth、router、error 等基础设施       |
| `src/stores`              | Pinia Store  | 按业务域拆分，禁止形成万能 Store              |
| `src/composables`         | 组合式逻辑   | 生命周期、交互状态和跨端能力封装              |
| `src/utils`               | 纯工具函数   | 不访问页面实例，不承载业务状态                |
| `src/constants`           | 全局常量     | Storage Key、错误码、路由名和事件名统一定义   |
| `src/styles`              | 全局样式系统 | config、tokens、mixins、utilities、components |
| `src/static`              | 静态资源     | 仅存放需要随包发布的资源，控制主包体积        |
| `src/config`              | 环境和常量   | 平台差异、环境变量和业务常量统一入口          |

推荐样式结构：

```text
src/styles/
├── _theme-config.scss   # 允许项目修改的主题配置源
├── _functions.scss      # tint、shade 等纯函数
├── _primitives.scss     # 原始色板、尺寸阶梯
├── _semantic.scss       # 文字、背景、边框、状态语义
├── _mixins.scss         # 安全区、文本截断、触摸区域等
├── _utilities.scss      # 高频原子类
├── _components.scss     # 全局基础组件样式
└── index.scss           # 唯一公共入口
```

`vite.config.js` 自动注入 Token、函数和 Mixin。业务样式只引用语义变量，不直接依赖原始色板。

## 20 条工程红线

以下规则约束数据、网络、状态、性能和平台能力；与后文 32 条样式强约束同时生效。

| 编号 | 红线                     | 判定标准                                                             |
| ---- | ------------------------ | -------------------------------------------------------------------- |
| R01  | 禁止嵌套列表渲染         | 页面模板中的业务 `v-for` 原则上不超过一层；复杂结构拆成子组件        |
| R02  | 响应式状态只存视图数据   | API 原始响应先转换，禁止把无关大对象整体塞入 `ref`、Store 或页面状态 |
| R03  | 平台能力优先使用 `uni.*` | 浏览器、微信和 `plus` API 必须由跨端适配层封装                       |
| R04  | 页面节点设置预算         | 常规页面目标不超过 1000 个节点，超出时必须拆分、分页或虚拟化         |
| R05  | 长列表必须分页           | 禁止一次加载全部数据；必须有加载中、结束和失败状态                   |
| R06  | 限制视图层通信量         | 单次跨逻辑层更新目标不超过 100KB，高频更新不得超过 20 次/秒          |
| R07  | 禁止动态执行代码         | 严禁 `eval`、`new Function` 及从服务端下载脚本后执行                 |
| R08  | 禁止硬编码配置           | 域名、Storage Key、错误码、路由、主题值和平台开关进入配置或常量层    |
| R09  | 请求必须防重复           | 查询请求按 key 合并；提交操作由按钮锁和服务端幂等共同保护            |
| R10  | 失败必须可感知           | 网络、权限、业务和解析失败均进入明确错误态，不得只写 `console`       |
| R11  | 页面禁止直调请求 API     | 只能调用 `src/api/modules` 暴露的领域方法                            |
| R12  | 禁止静默吞错             | `catch` 必须恢复状态、转换异常或继续抛出，禁止空 `catch`             |
| R13  | 禁止万能 Store           | 临时页面状态留在页面；Store 按业务域拆分并提供重置能力               |
| R14  | 禁止匿名 Storage Key     | 所有持久化 Key 由 `STORAGE_KEYS` 管理，并定义版本和清理策略          |
| R15  | 禁止裸字符串路由         | 页面路径和登录要求集中注册，通过路由封装跳转                         |
| R16  | 禁止无清理的副作用       | 定时器、监听器、Observer、订阅和请求任务必须随生命周期释放           |
| R17  | 禁止在模板执行重计算     | 排序、过滤、聚合和格式转换使用 computed 或预处理结果                 |
| R18  | 禁止复制平台页面         | 平台差异应隔离到 adapter、composable、service 或基础组件             |
| R19  | 禁止提交调试与秘密信息   | API Key、私钥、测试账号、调试入口和生产日志不得进入客户端包          |
| R20  | 禁止未验证就发布         | 至少完成目标平台构建、关键路径冒烟、隐私检查和包体积检查             |

R04、R06 是项目性能预算，不是平台能力上限。超过预算必须提供真实设备测量结果和保留理由，不能通过删除检查规则放行。

## 8 类基础开发规范

### API 架构

- `src/api/request.js` 只负责传输、协议归一化、鉴权衔接、超时、取消和错误转换。
- `src/api/modules/*.api.js` 负责领域接口和请求参数，不处理页面跳转或 UI Toast。
- 页面只调用领域 API；响应数据在 API 模块或 mapper 中转换为视图模型。
- Mock 与正式接口共享相同的请求、响应契约，不在页面中写 `if (useMock)` 分支。

### Pinia 状态管理

- 用户、权限、主题等跨页面状态进入 Store；弹窗开关、表单草稿等局部状态留在页面。
- Store 对外暴露语义 action，页面不得跨 Store 直接修改内部状态。
- 登录退出必须清理用户信息、权限、业务缓存和受保护的持久化数据。
- 持久化字段必须有版本；结构变更时提供迁移或显式失效策略。

### 路由与守卫

- 使用统一 `router.push`、`router.replace`、`router.back` 和 `router.reLaunch` 封装。
- 路由层负责页面路径、参数编码、登录拦截和页面栈保护。
- 页面接收参数后立即校验并转成业务类型，禁止在后续逻辑中反复读取原始 query。
- 接近页面栈上限时使用重定向或重启策略，不允许继续无界 `navigateTo`。

### Storage

```js
export const STORAGE_KEYS = Object.freeze({
  TOKEN: "auth_token",
  USER_INFO: "user_info",
  THEME: "app_theme",
});
```

- 业务代码通过 storage 封装读写，不直接散落 `uni.getStorageSync` 和 `uni.setStorageSync`。
- 每个 Key 定义所有者、数据结构、有效期、是否敏感以及退出登录时是否清理。
- Token 等敏感数据不得被埋点、日志、错误上报或调试面板输出。
- 缓存读取失败必须可以降级为重新请求，不能阻断应用启动。

### 埋点

- 事件名使用“页面_元素_动作”或项目统一命名法，并由常量集中管理。
- 页面曝光、关键点击、业务结果和失败原因分别记录，禁止把完整请求体作为属性上传。
- 用户标识、手机号、Token、精确位置等敏感数据必须脱敏或禁止采集。
- 埋点失败不影响主业务；开发环境可验证事件，但生产环境禁止输出敏感调试日志。

### 组件通信

| 关系           | 首选方式         | 约束                                               |
| -------------- | ---------------- | -------------------------------------------------- |
| 父到子         | props            | 只读输入，复杂对象明确字段契约                     |
| 子到父         | emit             | 使用业务事件名，不回传组件内部实现细节             |
| 祖先到后代     | provide / inject | 仅用于稳定上下文，必须提供默认值或缺失错误         |
| 跨页面共享     | Pinia            | 可追踪、可重置，不用全局变量                       |
| 临时跨组件事件 | Event Bus        | 仅在无直接关系且生命周期明确时使用，卸载时取消订阅 |

### 性能

- 页面节点、跨逻辑层数据量、图片体积、主包和分包均设置预算并进入发布检查。
- 长列表使用分页、窗口化或虚拟列表；禁止仅靠“加载更多”文案掩盖一次性全量渲染。
- `onShow`、滚动、输入和网络重试都要控制触发频率，禁止同一生命周期重复请求。
- 性能结论必须来自真机或平台分析工具，不以 H5 浏览器表现代替小程序和 App 结果。

### 错误与可观测性

- 错误统一转换为稳定的错误类型和错误码，页面只决定当前业务如何展示。
- 全局捕获未处理 Promise、Vue 运行时和网络异常；不得上传 Token、请求密钥和用户隐私。
- 上报包含平台、应用版本、页面、操作阶段和关联请求 ID，不上传无边界的完整状态快照。
- 用户可恢复的错误必须提供重试、返回或重新登录入口。

## 32 条强约束

### Design Token

1. 颜色必须使用语义 Token，禁止在页面和组件中硬编码 `#333`、`rgb()`、`rgba()` 等颜色。
2. 字号必须使用字号 Token，禁止出现无归属的 `30rpx`、`34rpx` 等临时值。
3. 间距必须来自 4rpx 阶梯，页面不得自行创造相近但不同的间距。
4. 圆角必须使用圆角 Token，卡片、按钮、弹窗不得各写一套。
5. 阴影必须使用阴影 Token，禁止在业务页面直接拼装 `box-shadow`。
6. z-index 必须使用层级 Token，禁止 `999`、`9999`、`99999` 竞争层级。
7. 动画时长和缓动曲线必须使用动画 Token。
8. 业务代码只能使用 semantic Token；primitive Token 仅供主题层生成语义变量。

### 样式与交互

9. 页面和业务组件的 `<style>` 必须添加 `scoped`；全局样式只允许存在于 `src/styles`。
10. SCSS 选择器嵌套不得超过 3 层，禁止依赖页面 DOM 层级覆盖组件。
11. 动画优先只改变 `transform` 和 `opacity`，禁止用 `top`、`left`、`height` 制造高频动画。
12. 所有非必要动画必须适配 `prefers-reduced-motion` 或项目的减少动画开关。
13. 可点击区域不得小于 88rpx × 88rpx；视觉元素较小时使用伪元素或容器扩大热区。
14. 点击态、禁用态、加载态必须可辨识；不得只依赖颜色表达状态。
15. 文本默认允许系统字号适配；关键布局不得因字体放大而遮挡、重叠或截断操作入口。
16. 图片必须声明宽高或 `aspect-ratio`，并提供加载占位、失败兜底和合理的 `mode`。

### 页面布局

17. 页面使用原生页面滚动；禁止用全页 `scroll-view` 替代页面滚动。
18. `scroll-view` 只用于明确高度的局部区域、横向列表或虚拟列表，不得形成多层同向滚动。
19. 页面左右留白统一使用 `$page-gutter`，不得由页面自行决定 24rpx、32rpx 或 40rpx。
20. 页面模块间距统一使用 `$section-gap`，模块内部使用 spacing 阶梯。
21. 自定义导航栏必须读取系统和胶囊信息；标题与胶囊按钮水平居中，不遮挡、不越界。
22. 顶部内容必须计入状态栏和导航栏高度，底部操作区必须计入 `safe-area-inset-bottom`。
23. 固定底部操作区使用统一组件或全局样式，页面不得重复实现宽高、阴影和安全区。
24. 空态、错误态、加载态必须占据稳定区域，状态切换不得造成明显布局跳动。

### 组件与项目

25. Popup、Modal、Drawer 必须包含进入和退出动画；内容消失后才能卸载遮罩。
26. 弹层打开时必须阻止背景滚动和穿透点击，关闭后恢复原滚动上下文。
27. 列表项统一使用“主内容 + 辅助信息 + 操作区”结构，分割线和点击态一致。
28. Input、Textarea、Picker、Switch 等表单控件必须由基础组件统一标签、错误态和禁用态。
29. Button 必须使用基础组件，业务页面禁止自行定义主按钮渐变、圆角和 loading 布局。
30. “暂无数据”等空列表内容必须使用 Empty 组件，禁止页面各写一套文案和插图。
31. 平台差异必须集中封装或使用条件编译；禁止在模板和业务流程中散落平台判断。
32. 禁止通过高优先级选择器、`!important` 或深度选择器掩盖设计系统问题；应修复 Token 或组件源实现。

## Design Token 四层架构

```text
Theme Config → Primitive → Semantic → Component / Utility
```

- **Theme Config**：品牌主色、文字基色、页面尺寸密度等项目配置。
- **Primitive**：50—900 色板、4rpx 间距阶梯、基础字号和原始尺寸。
- **Semantic**：`text-primary`、`bg-page`、`border-default`、`status-danger` 等用途变量。
- **Component / Utility**：Button、Popup、Card 与原子类消费语义变量。

### 文字色自动派生

```scss
$color-text-primary: #2b2e31;
$color-text-secondary: tint($color-text-primary, 30%);
$color-text-tertiary: tint($color-text-primary, 50%);
$color-text-disabled: tint($color-text-primary, 70%);
```

| 语义                    | 使用场景                     |
| ----------------------- | ---------------------------- |
| `$color-text-primary`   | 页面标题、卡片标题、关键数据 |
| `$color-text-secondary` | 描述、副标题、普通正文       |
| `$color-text-tertiary`  | 时间、作者、辅助说明         |
| `$color-text-disabled`  | 禁用文字、占位信息           |

主题色和文字色必须独立配置。品牌色可以是任意颜色，正文层级不得由品牌色直接派生。

### 字号、间距与圆角

| 系统     | 建议 Token                              | 使用原则                             |
| -------- | --------------------------------------- | ------------------------------------ |
| 字号     | `xs / sm / base / lg / xl / xxl / xxxl` | 形成 H1—H4、正文、说明等固定层级     |
| 间距     | `1—12`，每级 4rpx                       | 只使用阶梯值，不写临时值             |
| 页面留白 | `$page-gutter`                          | 所有页面主内容左右一致               |
| 模块间距 | `$section-gap`                          | 页面一级模块之间统一                 |
| 圆角     | `sm / md / lg / xl / full`              | 按组件语义选择，不按视觉感觉临时调整 |
| 阴影     | `sm / md / lg`                          | 只表达层级，不作为装饰堆叠           |

## Z-index 层级规范

| Token         |   值 | 场景                       |
| ------------- | ---: | -------------------------- |
| `$z-base`     |    0 | 普通页面内容               |
| `$z-raised`   |   10 | 卡片浮起、局部装饰         |
| `$z-sticky`   |  100 | 吸顶筛选、粘性区域         |
| `$z-fixed`    |  200 | 固定底部操作、页面浮动按钮 |
| `$z-navbar`   |  300 | 自定义导航栏               |
| `$z-dropdown` |  400 | Picker、Dropdown、局部菜单 |
| `$z-mask`     |  800 | 全局遮罩                   |
| `$z-popup`    |  900 | Popup、Drawer              |
| `$z-modal`    | 1000 | Modal、Dialog              |
| `$z-toast`    | 1200 | Toast、全局提示            |
| `$z-loading`  | 1400 | 全屏阻断 Loading           |
| `$z-system`   | 2000 | 强制升级、系统维护提示     |

新增层级必须修改全局表并说明遮挡关系，禁止只提高当前组件数值。

## 16 类组件规范

| 组件               | 强制要求                                                                      |
| ------------------ | ----------------------------------------------------------------------------- |
| Button             | primary、secondary、outline、text、danger 五类；统一 loading、disabled、hover |
| Popup              | 支持底部、居中、右侧三种动效；统一遮罩、内边距和关闭行为                      |
| Card               | 统一背景、边框、圆角、内边距和标题区域                                        |
| Modal              | 标题、正文、操作区结构固定；危险操作必须明确区分                              |
| Toast              | 文案简短；成功、警告、错误状态一致；不得遮挡核心操作过久                      |
| Input              | 统一 label、placeholder、清除按钮、错误态、禁用态和计数                       |
| NavBar             | 对齐状态栏与胶囊；支持返回、标题、右侧操作和占位高度                          |
| Divider            | 只使用语义边框色；可选文本分隔，不用于制造大面积间距                          |
| Badge              | 数量、状态两类；文字可读，不能只靠颜色区分                                    |
| ListItem           | 主标题、描述、元信息、尾部操作结构统一，保证最小触摸区域                      |
| Avatar             | 固定尺寸档位；提供默认头像、加载占位和失败兜底                                |
| Grid               | 列数、间距由属性控制；小屏下内容不得溢出                                      |
| Empty              | 统一图形、标题、描述和可选操作；文案由业务传入                                |
| Image              | 统一比例、占位、懒加载、错误图和预览行为                                      |
| Loading / Skeleton | 首屏贴近真实布局；局部更新保留旧数据；超时提供明确反馈                        |
| FixedActionBar     | 统一安全区、按钮排列、边框和阴影，不遮挡页面最后一项                          |

组件 API 使用语义属性，例如 `type="danger"`、`size="large"`，禁止暴露 `color="#f00"`、`radius="17rpx"` 这类破坏规范的任意视觉参数。

## Utility 原子类

原子类只覆盖稳定、高频、单一职责的布局与样式，不发展成完整 Tailwind 运行时，也不允许任意值语法。

```html
<view class="bg-white rounded-md p-4 shadow-sm flex-between">
  <view class="flex-col flex-1">
    <text class="text-primary text-lg font-semibold text-ellipsis">标题</text>
    <text class="text-secondary text-sm mt-2">描述</text>
  </view>
  <text class="text-tertiary text-xs ml-2">2026-08-03</text>
</view>
```

| 类别     | 示例                                                               |
| -------- | ------------------------------------------------------------------ |
| Flex     | `flex`、`flex-col`、`flex-center`、`flex-between`、`flex-1`        |
| Gap      | `gap-1` 至 `gap-8`                                                 |
| 间距     | `p-*`、`px-*`、`py-*`、`m-*`、`mt-*`、`mb-*`                       |
| 文字色   | `text-primary`、`text-secondary`、`text-tertiary`、`text-disabled` |
| 字号字重 | `text-xs` 至 `text-xxxl`、`font-normal` 至 `font-bold`             |
| 文本处理 | `text-ellipsis`、`text-clamp-2`、`text-center`、`break-all`        |
| 背景边框 | `bg-page`、`bg-white`、`border-default`                            |
| 圆角阴影 | `rounded-sm` 至 `rounded-full`、`shadow-sm` 至 `shadow-lg`         |

出现复杂状态、伪元素、多端差异或超过 6 个原子类时，应使用语义 class 或封装组件，避免模板退化为样式清单。

## 自定义导航栏与胶囊对齐

1. 通过 `uni.getSystemInfoSync()` 获取状态栏信息，通过 `uni.getMenuButtonBoundingClientRect()` 获取胶囊位置。
2. 导航栏内容高度以胶囊高度和上下间距计算，不写死某一机型数值。
3. 标题位于第一行可视导航区，与胶囊垂直中心对齐，并为右侧胶囊预留对称安全宽度。
4. 页面内容顶部使用统一占位高度；禁止每页自行补 `padding-top`。
5. 获取胶囊信息失败时使用全局兼容值，兼容逻辑集中在 NavBar 组件内。
6. H5、App 和非微信小程序平台由同一组件提供平台适配，不复制导航栏实现。

## 页面滚动与安全区

- 页面默认使用原生滚动，列表分页绑定页面触底生命周期。
- 横向分类、固定高度日志、大数据虚拟列表可以使用局部 `scroll-view`。
- 弹层内部滚动必须与页面滚动隔离，遮罩使用 `catchtouchmove` 或统一锁滚策略防止穿透。
- 固定底部区域必须添加 `padding-bottom: env(safe-area-inset-bottom)`，同时为页面内容预留等高空间。
- 下拉刷新不得清空已有数据；请求失败保留用户滚动上下文和已加载数据。
- 图片、Skeleton 和异步模块预留稳定尺寸，避免加载后滚动位置跳变。

## 请求层完整规范

### 职责边界

| 类别           | 规范                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 请求入口       | 统一封装 `uni.request`，业务代码只调用 `api/modules`                                |
| 返回结构       | 归一化为 `{ code, data, message }`，业务失败与传输失败统一转成可识别异常            |
| 鉴权           | 请求拦截器注入 Token；请求层只提供 401/403 衔接点，完整登录流程由 auth service 管理 |
| Token 刷新     | 并发 401 只允许一个刷新任务，其余请求进入等待队列；刷新失败只执行一次退出流程       |
| Loading        | 首次加载、刷新、分页、提交分别建模，禁止一个布尔值覆盖所有状态                      |
| 防重复         | GET 等幂等查询按稳定 key 合并；非幂等提交默认不自动重放                             |
| 取消与过期     | 页面卸载后取消任务或忽略过期响应，旧响应不得覆盖新状态                              |
| 错误处理       | 网络、超时、HTTP、业务、鉴权和解析错误分别编码，不直接展示后端堆栈                  |
| Mock           | 与正式 API 保持同一契约，通过环境配置切换，生产构建必须关闭                         |
| 文件上传       | 统一封装 `uni.uploadFile`；进度、取消、文件限制和错误结构与普通请求一致             |
| SSE / 流式响应 | H5 使用受控流式实现，小程序使用平台支持的 chunk 能力，并统一消息解析与取消          |

### 响应与异常契约

```js
/**
 * @template T
 * @typedef {Object} ApiResponse
 * @property {number} code
 * @property {string} message
 * @property {T} data
 */
```

- 成功码由 `SUCCESS_CODES` 集中配置，不在业务页面写 `code === 0` 分支。
- 业务错误码进入 `ERROR_CODE_MAP`；未知错误保留稳定兜底文案和关联请求 ID。
- HTTP 401、403、超时、断网、服务端异常分别映射为 `UNAUTHORIZED`、`FORBIDDEN`、`TIMEOUT`、`NETWORK_ERROR`、`HTTP_ERROR`。
- 请求封装返回业务 `data` 或抛出标准异常，项目内不得同时存在“有时返回完整响应、有时返回 data”两种习惯。

### 并发、去重与重试

- 请求 key 至少包含 method、规范化 URL、身份上下文和稳定序列化后的参数。
- 只有可安全共享结果的请求才能去重；创建订单、支付、上传等非幂等请求依赖交互锁和服务端幂等键。
- 自动重试只用于明确可恢复且幂等的网络失败，采用有限次数和退避策略；401 不进入普通重试。
- Token 刷新请求不得经过自身的鉴权刷新拦截器，避免递归死循环。
- 页面切换后，过期请求即使成功返回也不得更新已卸载页面或新一轮查询。

### Mock、上传与流式请求

- Mock 数据覆盖正常、空数据、分页结束、业务失败、超时和字段边界，不只提供理想成功样本。
- Mock 开关来自环境配置，Mock 文件不得被生产入口引用或包含真实用户数据。
- 上传前校验类型、数量和大小；上传中暴露进度与取消；失败后保留用户已选择文件。
- 流式请求必须支持手动中止、断流错误、增量解码和消息边界处理；UI 更新应批量合并，避免每个字符触发一次视图通信。

页面异步状态至少区分：`initialLoading`、`refreshing`、`loadingMore`、`submitting`、`streaming`、`empty`、`error` 和 `finished`。

## 多端条件编译规范

- 平台能力优先封装为 composable、service 或基础组件，再由业务层调用统一接口。
- 条件编译块保持最小，只包围真正不同的 import、API 调用或模板节点。
- 禁止复制整个页面分别维护微信、H5 和 App 版本。
- `#ifdef` / `#ifndef` 必须写明平台目标，公共分支为默认实现。
- App 权限申请、隐私协议和系统能力调用集中管理，页面只消费授权结果。
- 使用条件编译后必须至少验证主目标微信小程序；修改共享逻辑时同时验证计划发布的平台。

### App 端专项规范

- Android 系统返回键按“关闭弹层 → 返回上一页 → 双击或确认退出应用”的优先级统一处理。
- iOS 状态栏、安全区、权限用途描述和系统字体缩放必须真机验证，不能以 Android 结果代替。
- `plus.*`、原生插件、推送、定位、相机和文件能力集中封装，并使用条件编译隔离非 App 构建。
- `nvue` 与 Vue 页面不得默认共享全部 CSS 能力；使用 `nvue` 时单独核对布局、字体、动画和组件兼容性。
- Android 与 iOS 权限拒绝、永久拒绝和系统设置返回流程必须完整，不得无限重复弹窗。
- 热更新只能更新平台政策允许的资源和代码范围，必须校验签名、版本、完整性并支持失败回滚。
- App 包不得包含调试证书、测试服务器地址、明文密钥、未使用原生库和多余架构产物。
- 推送点击、冷启动、后台恢复和多次通知必须使用统一路由恢复逻辑，避免重复打开页面。

## 分包与性能规范

- 主包只保留启动页、TabBar 页面和首屏必需资源；低频业务进入分包。
- 分包之间禁止直接依赖页面代码；共享逻辑上移到主包公共模块，并控制体积。
- 页面和重组件按需加载，长列表使用分页或虚拟列表。
- 图片按展示尺寸压缩，非首屏图片启用懒加载；不得把大图作为 base64 写入源码。
- 高频滚动事件必须节流，避免在模板中调用高成本函数。
- `setData` 等跨逻辑层通信应减少数据量和频率，列表只更新变化部分。
- 避免在 `onShow` 无条件重复请求；根据数据时效和页面返回场景决定刷新。
- 定时器、事件监听、IntersectionObserver 和请求任务在页面卸载时清理。
- 主包、分包和 App 安装包设置明确预算；小程序发布前使用平台工具核对实际产物，不以源码目录大小代替。
- 依赖、页面、组件和静态资源需要定期做可达性检查；删除前同时核对 `pages.json`、条件编译、动态组件和分包引用。

## 深色模式

语义变量通过 CSS 变量桥接主题；组件不得直接判断“当前是否黑色主题”来选择硬编码颜色。

```scss
page {
  --color-bg-page: #f6f7f8;
  --color-bg-card: #ffffff;
  --color-text-primary: #{$color-text-primary};
}

page[data-theme="dark"] {
  --color-bg-page: #111315;
  --color-bg-card: #1b1e21;
  --color-text-primary: #f3f4f5;
}
```

- 同时支持系统主题和 `data-theme` 手动切换。
- 图片、遮罩、边框、阴影和 Skeleton 必须检查深色模式对比度。
- 主题切换不能导致页面重新创建或丢失滚动、表单状态。

## 代码审计体系

### 审计原则

综合代码审计只检查并输出 `uniapp-audit-report.md`，不得修改、修复、格式化或重构项目。体检和治理分开：先固定证据、范围和风险等级，再由对应规范或专项任务修复。

审计必须先记录：

- 范围：全量、指定目录/模块、抽样或 Git 未提交改动；
- 目标平台：微信小程序、其他小程序、H5、Android App、iOS App；
- 项目形态：Vue 2 / Vue 3、JavaScript / TypeScript、CLI / HBuilderX；
- 重点维度和明确排除项；
- 使用的构建配置、环境和可获得的产物。

平台专项规则仅在目标平台包含该平台时执行。无法确认的问题标记为“待验证”，不得把静态推测写成确定缺陷。

### 10 大审计维度

| 维度         | 必查内容                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------- |
| 安全与合规   | API Key、Token、私钥、测试账号、生产日志、危险 API、合法域名、隐私政策、权限最小化、依赖漏洞 |
| 性能         | 主包与分包、App 包体积、图片、请求瀑布、长列表、视图层通信、缓存、启动与页面渲染             |
| 代码质量     | 类型或 JSDoc、硬编码、重复逻辑、异常处理、生命周期清理、组件边界、测试覆盖                   |
| 架构与规范   | 目录、工程红线、配置、状态管理、路由、Storage、构建、lint 和环境隔离                         |
| UI 与主题    | 颜色、字号、间距、圆角、阴影、z-index、基础组件复用、交互状态、深色模式                      |
| 跨平台兼容   | H5 标签、浏览器 API、CSS 能力、条件编译、安全区、平台适配层及三端表现差异                    |
| 小程序专项   | 页面栈、主包与分包、合法域名、隐私接口、版本更新、胶囊导航、视图通信和审核限制               |
| App 端专项   | Android/iOS 差异、系统返回、权限描述、`plus`、`nvue`、原生插件、热更新、推送和包安全         |
| 冗余与死代码 | 未注册或未引用页面、组件、函数、样式、静态资源、注释旧逻辑、重复实现和无用依赖               |
| API 契约     | 请求入口、响应结构、Token 注入、刷新队列、401/403、去重、幂等、Mock、上传和流式请求          |

死代码结论必须核对静态 import、`pages.json`、分包、easycom、动态组件、条件编译、路由字符串和原生插件引用。仅靠文本搜索不能判定文件可删除。

### P0—P3 风险分级

| 等级          | 定义                                                           | 典型问题                                                    |
| ------------- | -------------------------------------------------------------- | ----------------------------------------------------------- |
| P0 / Critical | 可能导致审核被拒、数据或密钥泄露、远程代码执行、支付或鉴权失守 | 明文生产密钥、`eval` 执行外部内容、隐私能力未声明           |
| P1 / High     | 明显影响核心功能、稳定性、性能或目标平台可用性                 | 刷新 Token 并发失控、Android 返回直接退出、主包超过发布限制 |
| P2 / Medium   | 影响可维护性、规范一致性或局部体验                             | 重复组件、缺少生命周期清理、主题硬编码、错误态不完整        |
| P3 / Low      | 风险较低的优化建议或轻微偏差                                   | 可读性、非关键资源压缩、局部命名和结构改进                  |

等级由“影响 × 发生概率 × 可发现性”决定，不能只按规则名称机械定级。平台限制、包体积和依赖漏洞必须基于本次审计目标平台及当前工具输出，不引用过时固定值。

### 审计模式

- **全量审计**：上线前或接手旧项目时执行 10 个维度。
- **增量审计**：只检查 Git 未提交差异，同时追踪受影响调用链、配置和生成产物；不能只看改动行。
- **专项审计**：只检查安全、性能、请求层、App 等指定维度，报告必须声明未检查项。
- **抽样审计**：大项目按业务模块和风险分层抽样，列出样本选择方法，结论不得外推为“全项目通过”。

### 报告格式

每条问题必须包含：

1. 唯一编号、风险等级和审计维度；
2. 文件路径、行号或产物位置；
3. 可复核的代码、配置、命令输出或运行现象；
4. 影响范围和触发条件；
5. 判定依据及适用平台；
6. 修复方向，但不在审计阶段改代码；
7. 置信度，以及需要真机、后台配置或人工补证的内容。

报告首页汇总 P0—P3 数量、各维度健康度、平台覆盖、阻断发布项和未完成检查。未发现问题只能表述为“在已检查范围内未发现”，不能表述为绝对安全。

### 样式 lint 与自动修复边界

样式 lint 默认扫描 `src/pages`、`src/pages-sub` 和自有 `src/components`，排除第三方依赖、构建产物和 `_theme-config.scss`。它可以作为独立修复任务处理确定性违规，但不属于只读代码审计。

必须检查硬编码 Token、缺失 `scoped`、超过 3 层嵌套、`!important`、任意高 z-index、过小触摸区、全页 `scroll-view`、无动画弹层、未处理安全区的固定元素、无稳定尺寸的图片，以及页面重复实现的基础组件。

自动修复只处理语义明确且可验证的值。无法判断时只报告位置和候选 Token；不得修改业务逻辑、第三方代码和主题配置源。
