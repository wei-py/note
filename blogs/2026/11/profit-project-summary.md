# Profit 项目总结

一句话定位

面向跨境电商卖家（巴西-美客多 Mercado Livre 为首要场景）的商品利润/费用试算 + 商品记录管理桌面工具。核心思想：用一份 Excel
配置驱动「算什么、怎么算」，卖家只填商品信息，自动算出佣金、运费、净利润、利润率。

│ 主应用（src/ + src-tauri/） │ Vue 3 + Pinia + Tauri 2 + Vite，纯 JS │ 桌面端（也可部署 Web 到 Cloudflare Pages），含配置页、商品页、激活页 │
├─────────────────────────────┼───────────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ API Worker（api/worker.js） │ Cloudflare Workers + D1 + R2 │ 激活码签发/校验、设备绑定、文件托管（远程配置 Excel、安装包、version.json） │
├─────────────────────────────┼───────────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────┤

技术栈硬性约束（readme + AGENTS.md）：Vue 3 + JavaScript（禁止 TypeScript）、Vite + pnpm、daisyUI、Pinia、xe-utils 做运算/判空、dayjs 做日期、xlsx
为唯一数据源且配置与业务数据分离。

三、核心需求（功能性）

### 1. 总原则：两个 Excel，互不写回

- 配置.xlsx：唯一配置源，只管「怎么算」，不管商品记录。
- 列表.xlsx：独立文件，存算好的商品记录，列表页保存时同步到它，绝不写回配置。
- 配置支持远程 URL 加载（指向 admin 后台托管的 default.xlsx），用远程配置时不可保存。

### 2. 配置.xlsx 的四个固定 sheet + N 个查表

┌────────────┬────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ sheet │ 需求 │
├────────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 国家平台 │ 维护「国家+平台」组合（巴西-美客多），含货币、汇率、启用、排序 │
├────────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算字段 │ 定义组合下的参数项：字段名、类型（文本/数字/下拉/布尔）、单位、选项组、默认值、必填、层级、输入输出、排序 │
├────────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 选项配置 │ 可复用枚举值，支持多级父子级联（如「动物与宠物/鸟/鹌鹑」），用「选项值编号」保证唯一性，可参差不齐、可选中父级 │
├────────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 计算配置 │ 费用模板，挂在组合下，核心是 流程JSON（规则 DAG，见 §4） │
├────────────┼────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ *表/*table │ 查表数据（类目佣金查询表等），名字含「表/table」自动收集为 lookupTable │
└────────────┴────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

字段两个关键维度：

- 层级：平台级（整组合共用）/ 商品级（一个商品共用）/ SKU级（每个 SKU 各填）
- 输入输出：输入（用户填）/ 输出（引擎算）

### 3. 配置页（/country）

- 组合、字段、选项组、模板四类列表，均支持拖拽排序（顺序要同步写回 Excel 的「排序」列）、CRUD、弹窗编辑、上下移动。
- 层级式：组合 → 展开 → 字段/选项组/模板三块。
- 每个弹窗、每个操作区域右上角有「?」教学引导（driver.js，用户点击才触发，不自动弹）。
- 规则编辑的条件树：AND/OR 条件组无限嵌套，「+ AND 条件」「+ OR 条件」，单击切换 AND↔OR。
- 保存配置走 Web Worker 导出防卡顿；未绑定文件时保存要弹「另存为」；有 localStorage 草稿（未保存编辑按文件 mtime 恢复）。

### 4. 规则引擎（最核心的需求演进）

从硬编码费率 → 条件规则 → 可视化 DAG 图编辑器（Vue Flow，src/services/graph-engine.js + domain/rule-graph.js）：

- 一个模板 = 一个 flow = 多条 rule（可切换、排序、启停）；一条 rule = 一个 DAG 画布（节点+边）。
- 8
  种节点：input（输入，支持级联取整路径/末级）、constant、lookup（查表，如类目佣金表）、pick（从查找行取列，列名可来自上游节点实现「动态取列」）、map（值映射
  ：经典→classic）、calc（四则运算，正则白名单防注入）、condition（比较分支）、output。
- 规则按序执行，后面规则可用前面规则的输出（累积上下文）。
- UI 要求：左侧规则列表、中顶部新增节点、右侧节点列表、右下角规则/SQL 预览。
- 典型链路：售价 → 销售佣金金额=售价×佣金费率 → 支付手续费=售价×4.8% → 总费用=佣金+运费+手续费 → 净利润=售价−总费用−成本价 → 利润率=净利润÷售价。
- 批量计算放 Web Worker（Pinia reactive 需转纯对象 postMessage），无 Worker 环境同步降级。

### 5. 商品页（/list，创建 + 列表合一）

创建流程：选组合 → 选模板（自动填默认值）→ 填商品级字段（下拉类型渲染为下拉）→ 配变体 → 生成 SKU → 引擎计算。

- 变体/SKU：变体值支持 |,，;；、 任意分隔，多属性笛卡尔积；SKU 码 = 自定义前缀 + 起始序号(可自定义如001/011，补3位) + 变体属性；重算时按 key
  保留已填输入；SKU 可手动改。
- 保存到列表：SKU 拍平成记录行；编辑态（从记录回填的）按 商品ID 原位替换整组而非追加。
- 列表管理：按 商品ID 分组（斑马纹按组着色、整组拖拽）、分页不拆散商品组、记录回填编辑（反推变体属性）、复制同商品 ID 到新建面板。
- 反推计算：售价/净利润/利润率三者任改一项，正向引擎 + 二分查找（30 次迭代）反推另两项。
- 计算追溯：每个输出字段旁「?」弹窗，展示完整计算过程（查了什么表、条件命中了什么、所以费率是多少），traces 与计算同源产出。
- 图片：可上传/删除/预览缩放；存本地图片路径字段；列表 Excel 中用 WPS DISPIMG 方案嵌入单元格（cellimages.xml + =DISPIMG("ID\_...",1) 公式注入/解析），不用
  base64。

### 6. 激活授权（商业化需求）

- Tauri 端采集设备指纹（hostname+OS 的 SHA256）→ Worker /api/activate 激活并绑定设备 → D1 存储。
- 7 天离线宽限期（本地 Tauri Store 缓存），启动时静默 /api/validate。
- 激活码：PFT-XXXX-XXXX 格式，可设设备数上限、有效期；删除时若已绑设备自动转「撤销」不影响已激活用户。
- 管理双通道：pnpm code CLI + Admin Web（创建、改过期时间/状态/备注、备注模板、批量创建、详情含设备列表）。
- Admin 还带 R2 文件管理（上传/重命名/删除/公开链接/toggle），远程配置 Excel 和安装包都走这里。

### 7. 发布与自动更新

- package.json.version 为唯一版本源，sync-version.cjs 同步到 tauri.conf/Cargo.toml/version.json。
- pnpm tbuild 打包 + 私钥签名（updater artifacts），pnpm release:upload 传 R2 并生成远端 releases/version.json（signature 必须是 .sig 文件内容，不是
  URL——文档里记录的坑）。
- App 内 Tauri updater 读 version.json、下载、内置公钥验签后安装；manual 字段供手动下载 dmg/exe。
- Web 版：pnpm build && wrangler pages deploy dist --project-name profit。
- GitHub Actions CI/CD（build-exe）。

六、设计地基（最值得记住的 4 条）

1.  配置驱动一切：表单字段、默认值、下拉、计算逻辑全来自 Excel，改规则不改代码。
2.  配置与业务彻底分离：分文件、分 store、互不写回。
3.  DAG 规则引擎是整个项目的灵魂，流程JSON 存进配置即可扩展新费用规则；计算时顺带产出人话 traces。
4.  双端同一套代码：Tauri 桌面为主，同一份代码可发 Cloudflare Pages Web 版，差异收敛在 useFileIO 等少数适配层。
